# 调试与日志规范

## 一、OpenHarmony 崩溃日志获取规范

### 1.1 核心约束
- `/faultlog/`、`/data/crash/` 等路径受 **SELinux** 严格保护，普通 `hdc shell` 无权访问
- 使用 `hdc shell ls /data/log/faultlog/` 会返回 `Permission denied`
- 崩溃日志 **只能通过实时 hilog 捕获**，无法读取静态文件

### 1.2 实时日志捕获命令
```powershell
# 启动实时日志（Windows PowerShell）
hdc hilog -x | Select-Object -First 200

# 过滤特定 TAG
hdc hilog -x -t SciDAVis | Select-Object -First 100

# 过滤崩溃级别
hdc hilog -x -t SciDAVis -l FATAL
```

### 1.3 重要注意事项
- **必须在应用运行时立即执行** hilog 捕获，延迟会导致日志丢失
- 崩溃日志是易失性的，重启设备后历史日志不可恢复
- 建议在每次启动应用前启动 hilog 捕获
- 结合 `hilog` 命令超时或返回空结果时，检查设备连接状态

### 1.4 日志分析关键词
- `cppcrash` — C++ 层崩溃
- `js crash` — ArkTS/JS 层崩溃
- `SIGSEGV` — 空指针/段错误
- `request js object: JsLocale` — QPA JS 桥接未正确初始化
- `TypeError` — NAPI 模块未就绪或类型不匹配

## 二、Windows 下 hdc shell 管道使用规范

### 2.1 核心约束
在 Windows 环境下使用 `hdc shell` 命令时，管道后**不能使用 Unix 工具**（`head`、`grep`、`tail` 等）。

### 2.2 正确用法
必须改用 **PowerShell 的 `Select-Object`** 和 **`Select-String`**：

```powershell
# 替代 head -n 50
hdc shell 'hilog -x' 2>&1 | Select-Object -First 50

# 替代 grep "Error"
hdc shell 'hilog -x' 2>&1 | Select-String -Pattern "Error"

# 组合使用
hdc shell 'hilog -x' 2>&1 | Select-String -Pattern "SciDAVis" | Select-Object -First 30
```

### 2.3 常见错误
```powershell
# 报错：'head' is not recognized as an internal or external command
hdc shell 'hilog -x' | head -n 50

# 报错：'grep' is not recognized
hdc shell 'hilog -x' | grep "Error"
```

## 三、hilog 后台流维护规范（2026-07-27 补充）

### 3.1 核心结论
- `hilog -x -z N` 的 dump 模式对历史崩溃/事件日志**无效**，必须用后台流式捕获：
  `hdc shell hilog -x > hilog_stream.txt`（后台进程）；
- 后台流会随 **hdc 重连、应用重启、设备断开**而静默死亡（文件停止增长，无报错）；
- **每轮验证前必须：重启流 → 确认文件正在增长 → 再执行操作**，否则会把“日志没抓到”
  误判为“事件没发生”（当日因此三次误判）。

### 3.2 验证流存活
```powershell
# 重启流后，确认文件大小在增长再开始测试
(Get-Item hilog_stream.txt).Length; Start-Sleep 2; (Get-Item hilog_stream.txt).Length
```

## 四、uitest 自动化验证命令规范（2026-07-27 补充）

### 4.1 命令名与参数精确性（踩坑实录）
| 目的 | 正确命令 | 错误用法 |
|---|---|---|
| 双击 | `hdc shell uitest uiInput doubleClick <x> <y>` | `dbClick`（报 Invalid parameters） |
| 向已聚焦控件输入 | `hdc shell uitest uiInput text <内容>`（无坐标） | `inputText <x> <y> <内容>` 会**先点击坐标**，破坏 doubleClick 已激活的单元格编辑态 |
| 回车确认 | `hdc shell uitest uiInput keyEvent 2054` | — |

单元格录入标准序列：`doubleClick` 激活编辑 → `text <值>` 聚焦输入 → `keyEvent 2054` 提交。

### 4.2 坐标换算
- 截图（snapshot）坐标 → 物理触控坐标需乘缩放系数（本机 2456×1600 为 **×1.228**）；
- 每次分辨率/设备变更后需重新标定：点击已知控件对比截图高亮位置。

## 五、dumpLayout hit-test 定位点击拦截者（2026-07-28 补充）

### 5.1 适用场景
控件点击"被吞"（无 hilog 分发、无弹窗、无崩溃）时的决定性排查手段，
禁止以调整坐标、加延时等猜测方式反复试错。

### 5.2 操作步骤
1. 在失败现场（复刻脚本序列到出错步骤，勿手动重开应用）执行
   `hdc shell uitest dumpLayout -p /data/local/tmp/dump.json` 并 `file recv` 取回；
2. 落盘 Python 脚本（勿用 `python -c` 内联，见 6.2）：递归遍历 JSON，对目标坐标
   (x,y) 打印每个 `bounds` 包含该点的节点的 type/bounds/enabled/clickable，按深度缩进；
3. z 序最上层（遍历中最后出现）的可点击节点即拦截者；结合 `snapshot_display` 截图佐证。

### 5.3 实录
Plot 组按钮 (1969,96) 点击无响应，hit-test 输出 `Column [1277,79][2407,1039]`
位于工具栏节点之上——Results Log 浮动面板遮挡，据此一次定位根因（面板 y 常量错误）。

## 六、Windows 控制台环境陷阱（2026-07-28 补充）

### 6.1 Python 输出编码
Windows 控制台默认 GBK，Python 打印 ✓、中文等字符抛 `UnicodeEncodeError` 直接崩溃。
两种防护任选其一（脚本内建更可靠）：
```powershell
$env:PYTHONIOENCODING='utf-8'; python tools\verify_toolbar.py
```
```python
import io, sys
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
```

### 6.2 禁止 PowerShell 内联 python -c 复杂代码
f-string 中的引号、`*`、`{}` 会被 PowerShell 解析器先行吞掉（ParserError 或语义悄变），
且难以察觉。**一律落盘 .py 文件后执行**；同理，委派/修补脚本落盘 .ps1 后用 `-File` 执行。
