## 二、三个真缺陷：现象 → 取证 → 根因 → 修复 → 验证

### C-1 未适配按钮不弹对话框
- **现象**：open_template/save_template/print/export_pdf 等 ✖ 项点击后静默，`resp.success===false` 分支永不命中。
- **取证**：hilog 显示 menuAction 返回 `{"success":true,"queued":true}`；对照 main.cpp 命令注册表——menuAction 属 mutation 命令，scidavis_call 队列化后立即返回，Qt 侧 `jsonError("unsupported on device")` 走 QueuedConnection，永远到不了 ETS 的同步返回值。
- **修复**：MainLayout.ets 新增 `MENU_ACTION_SUPPORTED` 白名单（15 项，与 main.cpp L1296-1357 镜像同步），default 分支先查白名单，不在名单直接 showNotAdapted()，不发 Qt。
- **验证**：run4 起 4 个未适配按钮全部正确弹窗。

### C-2 建表后 Edit/Plot 组仍灰显
- **现象**：新建 Table 后 uiState 已返回 `type=Table`，但 cut/copy/paste/delete 与 Plot 组按钮仍不可点。
- **取证**：debug 脚本读取菜单栏确认 uiState 数据正确到达 ETS，排除数据链路；问题定位在渲染层。
- **根因**：ArkTS `@Builder` 按值传参在首次渲染时冻结实参，@Prop 后续更新不触发 Builder 重渲染（官方文档规定按引用传参才具响应性）。
- **修复**：ToolBar.ets 两个 Builder 改为单对象字面量按引用传参（`ToolButton($$: TbButtonOpts)`），38 处调用点同步重写。
- **验证**：run4 起建表后 Edit 组 4 按钮全部正确派发。

### C-3 Plot 组点击被静默吞掉
- **现象**：脚本中 Plot 组 10 项持续 FAIL，但手动逐一点击全部正常——典型"脚本序列依赖"缺陷。
- **取证**：用复刻脚本序列的取证脚本复现失败，再用 hit_test.py 对 dumpLayout 按坐标 (1969,96) 做包含关系逐层打印，发现拦截节点 `Column [1277,79][2407,1039]`——Results Log 浮动面板盖住了工具栏右半带。
- **根因**：面板 `position.y = MENUBAR_HEIGHT_VP+8`（36vp）落在工具栏带（65..127px）之内；脚本对 log 按钮盲双击 toggle，一次 uiInput 丢击即奇偶错位使面板滞留。
- **修复**：双侧修复——ProjectTree/Results Log 两面板 y 改 `TOP_CHROME_VP+8`（68vp，工具栏之下）；脚本增加 ensure_log_panel_closed()（dump 找面板文本，存在则点 ✕）。
- **验证**：run6 全部 39 项 PASS；截图证实面板顶部位于工具栏之下。

## 三、技术经验与最佳实践

1. **hit-test 是定位"点击被吞"的决定性手段**：dumpLayout 全量 JSON 按 (x,y) 包含关系逐层打印 type/bounds/enabled/clickable，可直接找出拦截者，优于任何猜测式排查。
2. **queued 命令的错误不可达性**是本混合架构的固有语义：所有 mutation 命令的失败都无法通过同步返回值感知，ETS 侧必须对"能力协商"类判断（是否已适配）自建白名单，且与 C++ 注册表镜像同步。
3. **@Builder 响应性契约**：@Prop/@State 驱动的 Builder 参数必须走按引用（单对象字面量）形式；按值传参只适用于静态一次性内容。
4. **自动化回归脚本的抗扰设计**：弹窗断言轮询（3×1.2s）、失败后清扫（关残留对话框/菜单）、下拉首击吞掉重试、面板状态显式校验——缺少任何一环都会把"迟到弹窗污染"误判为功能缺陷。
5. **假阳性警惕**：run5 中 Graph 组 greyed 的 10 项 PASS 有部分处于面板遮挡之下，"点击无反应"恰好与"灰显不派发"预期一致——断言通过不等于路径正确，需 dumpLayout enabled/opacity 双证。
6. **undo 栈时序**：新建 aspect 即入 Qt undo 栈（undoEnabled 变 true），undo/redo 灰显断言必须安排在建表之前。
7. **Windows 环境陷阱**（复发两次，已固化）：Python 输出含 ✓ 等字符必须 `$env:PYTHONIOENCODING='utf-8'`（GBK 控制台 UnicodeEncodeError）；PowerShell 内联 `python -c "...f-string..."` 引号/星号被外壳吞（ParserError），取证脚本一律落盘 .py 执行。
8. **bindMenu 首击偶发吞掉**：设备实测第 1 次 uiInput click 无菜单、第 2 次弹出；脚本重试 3 次防御（面板遮挡修复后现象大幅减少，防御保留）。
