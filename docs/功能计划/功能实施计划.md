# SciDAVis OpenHarmony 功能实施计划（Feature Implementation Plan）

> 本文档面向 AI 助手（Harness / 子 agent），系统性描述 SciDAVis 的全部核心功能特性，
> 按 **从易到难** 的顺序给出实施路线，目标是使鸿蒙适配版与 Windows/macOS 版在
> **用户体验** 和 **文档格式兼容性** 上达到基本一致。
>
> 配套文档：
> - 架构与操作边界：`docs/开发指南/HARNESS_AI_GUIDE.md`
> - 编码/构建/调试规范：`docs/开发指南/开发规范指南.md`
> - 七大规范：`docs/开发规范/01`~`07`
>
> 优先级定义：**P0** = 基本可用性必需；**P1** = 桌面版核心功能对齐；**P2** = 进阶功能；**P3** = 可选/长期。

## 一、当前基线（2026-07 现状盘点）

### 1.1 技术架构（不可变更的前提）

```
ArkTS 前端 (ArkUI)  ←NAPI→  qohos.cpp 桥接层  ←dlsym→  Qt/C++ 后端 (libentry.so)
  UI 忠实复刻桌面版            sendMouse                 scidavis_call(cmd, jsonArgs)
  菜单/对话框/表格/画布        callQtCommand              ApplicationWindow (真实计算引擎)
```

- Qt 作为 **计算与文档引擎** 在后台运行；ArkTS 负责 **全部可见 UI**。
- 所有功能通过 `qtInjector.callQtCommand(cmd, argsJson)` → `scidavis_call` JSON 协议调用。
- 数据展示采用 **查询-渲染模式**：Qt 端序列化 JSON（如 `getTableData`/`getPlotData`），ArkTS 端组件（`DataTable.ets`/`PlotCanvas.ets`）渲染。

### 1.2 已实现的命令通道（scidavis/src/main.cpp `scidavis_call`）

| 命令 | 类型 | 状态 |
|------|------|------|
| `ping` | 查询 | ✅ |
| `getTableList` / `getTableData` | 查询 | ✅ |
| `getPlotList` / `getPlotData` | 查询 | ✅ |
| `newTable` / `setCellValue` | 变更 | ✅ |
| `importASCII` / `exportASCII` | 变更 | ✅（无 UI 参数面板打磨） |
| `menuAction`（new_notes/new_matrix/undo/redo/cut/copy/paste/delete） | 变更 | ✅ 部分路由 |

### 1.3 硬约束（每个功能实施前必读）

| # | 约束 | 影响 |
|---|------|------|
| C1 | 单窗口 QPA：Qt 端创建 QDialog/QMessageBox 顶层窗口会 SIGSEGV | **所有对话框必须用 ArkTS 实现**，参数通过 JSON 传给 Qt |
| C2 | 死锁防护：变更命令 fire-and-forget、查询命令 3s 超时（main.cpp 注释 20260727155932） | 变更命令**不能同步取返回值**；变更后需再发查询命令刷新 UI |
| C3 | QPA `handleKeyEvent` 生成的 `QKeyEvent::text()` 恒空 | 文本输入必须走 IME 通道（`insertText`/`deleteLeft` 等）或 JSON 直传 |
| C4 | 左键触摸事件由 Qt 层 InputProbe 跨源去重（60ms 窗口） | 不得在 ETS 层再做去重逻辑 |
| C5 | 坐标：ETS vp × 1.5 = 物理 px；`QT_ENABLE_HIGHDPI_SCALING=0` | 所有转发坐标必须 `vp2px()`；内容区需 `+menuOffsetY` |
| C6 | `scidavis/` 源码修改默认需用户授权（HARNESS_AI_GUIDE §2.1） | 本计划涉及的 Qt 侧改动**限定在 `scidavis/src/main.cpp` 的 `scidavis_call` 分发器扩展**，实施前须获得用户对该文件的授权确认 |
| C7 | OHOS 应用沙箱：Qt 端只能访问沙箱内路径 | 外部文件必须经 ArkTS `@ohos.file.picker` 选取后拷入沙箱，再把沙箱路径传给 Qt |
| C8 | 禁止修改构建配置、禁止 `any`/`require()`、UI 缩放只允许 `QT_SCALE_FACTOR` | 见 HARNESS_AI_GUIDE §2.2、§6.3 |

### 1.4 每个功能统一的实施闭环

```
根因分析 → 编码（ETS / qohos.cpp / main.cpp 分发器）→ hvigorw assembleHap
→ hdc install -r → 真机验证（启动/输入/稳定/交互 四维）→ git commit（用户确认）
```

## 三、阶段一：基础 UI 交互闭环（P0，先行）

> 目标：让"点得到、看得见、输得进"三件事在真机上 100% 可靠。这是所有后续功能的地基。

### F-01 菜单系统补全与行为一致性 — P0

- **描述与预期行为**：ArkTS `MenuBar.ets` 完整复刻桌面版菜单树（File/Edit/View/Scripting/Graph/Table/Analysis/Windows/Help），含分隔线、快捷键提示文本、禁用态（如无选中表格时 Analysis 灰显）。行为对齐 Windows 版：点击展开、hover 切换已展开菜单、外部点击/选中项后关闭、多级子菜单（如 New ▸ New Table/New Matrix/New Graph/New Note）。
- **关键挑战**：hover 切换与外部点击关闭在触摸设备上的正确性（HARNESS_AI_GUIDE §四 P1 已列调查方向）；菜单项禁用态需要从 Qt 查询当前上下文（活动窗口类型）。
- **依赖**：无（其余所有功能的入口）。
- **验证标准**：逐项点击全部菜单项，hilog 记录每项触发；与 Windows 版截图逐菜单同屏对比；外部点击关闭率 100%；hover 切换无闪烁。
- **备注**：未实现的功能菜单项必须弹 ArkTS Toast「功能开发中」，禁止静默无响应。

### F-02 工具栏 — P0

- **描述与预期行为**：菜单栏下方一行图标工具栏，复刻桌面版默认工具集：New Project/Open/Save、New Table/Matrix/Note/Graph、Cut/Copy/Paste、Undo/Redo、Plot 快捷按钮（Line/Scatter/Bar…）。按钮点击复用 F-01 的同一 `onMenuItemClick` 分发。
- **关键挑战**：图标资源需从 `scidavis/scidavis/icons/` 提取转 PNG 放入 ArkTS resources；禁用态与菜单联动。
- **依赖**：F-01（共用命令分发）。
- **验证标准**：每个按钮触发与对应菜单项完全一致的行为；图标视觉与桌面版一致。

### F-03 MDI 窗口管理 — P0

- **描述与预期行为**：桌面版是 MDI 多文档界面（多个 Table/Graph/Matrix/Note 子窗口）。鸿蒙版采用 **标签页/窗口列表** 模型：Windows 菜单和底部标签栏列出全部子窗口，支持激活（切换当前显示的窗口）、关闭、重命名、最小化(隐藏)。同一时刻内容区只显示一个活动窗口（符合已有"每次仅显示一个子窗口"约束）。
- **关键挑战**：需在 `scidavis_call` 新增 `getWindowList`（返回 name/type/label/active）、`activateWindow`、`closeWindow`、`renameWindow` 四个命令；窗口关闭需处理 Qt 端 `MyWidget::askOnCloseEvent`（必须先关闭确认对话框设置，避免 Qt 弹 QMessageBox 触发约束 C1 崩溃）。
- **依赖**：F-01。
- **验证标准**：新建 3 个表格 + 1 个图 → Windows 菜单列出 4 项 → 逐个激活切换内容区正确刷新 → 关闭一个后列表更新 → 15 分钟操作无 appfreeze。

### F-04 状态栏与结果日志 — P1

- **描述与预期行为**：`StatusBar.ets` 显示当前活动窗口名、鼠标坐标（图表内）、操作提示。View ▸ Results Log 显示 Qt 端分析结果文本（拟合报告等写入处）。
- **关键挑战**：新增 `getResultsLog` 查询命令（读取 `ApplicationWindow::results` 文本）；日志更新时机（每次分析命令完成后 ArkTS 主动拉取，不做 Qt→JS 推送以规避死锁 C2）。
- **依赖**：F-03（活动窗口概念）。
- **验证标准**：执行一次列统计后 Results Log 面板出现与桌面版格式一致的文本。

### F-05 键盘输入管道（单元格/文本编辑） — P0

- **描述与预期行为**：点击表格单元格 → 弹出软键盘/接受蓝牙键盘 → 输入文本/数字 → Enter 提交并下移一格、Tab 右移、Esc 取消、方向键移动焦点。Notes 编辑器支持多行文本输入。
- **关键挑战**：约束 C3——QPA 键盘事件 text 恒空，**不能依赖 Qt 原生键盘链路**。方案：ArkTS 侧用 `TextInput` 组件承接输入（DataTable.ets 内嵌编辑框），提交时走 `setCellValue`；对必须进 Qt 的场景用 QPA IME 通道 `insertText`/`sendEnterKey`/`deleteLeft`/`moveCursor`。方向键可用 `sendMouse` 模拟点击目标单元格替代。
- **依赖**：F-01；被 F-13/F-14/F-20 依赖。
- **验证标准**：真机蓝牙键盘 + 软键盘各完成一轮"输入 10 个单元格数值 → getTableData 回读全部一致"；Enter/Tab/Esc 行为与桌面版一致；中文输入不乱码。

### F-06 鼠标/触摸输入精度 — P0

- **描述与预期行为**：单击、双击（打开图层编辑等）、长按=右键菜单（触摸习惯映射）、拖拽（选区、移动图例）在 Qt 内容区内与光标位置像素级一致。
- **关键挑战**：HARNESS_AI_GUIDE §四 P0 的坐标偏移问题（menuOffsetY、vp2px、QWindow/XComponent 尺寸对齐）；双击需在 ETS 侧检测双击间隔并注入 `QEvent::MouseButtonDblClick`（需给 `scidavis_inject_mouse` 的 action 参数扩展双击枚举值，涉及 main.cpp）；拖拽序列 press→N×move→release 的事件顺序与丢帧。
- **依赖**：无；被 F-15/F-16/F-17 强依赖。
- **验证标准**：十字五点点击 ETS/Qt 坐标差 ≤1px；双击表头触发列编辑；拖拽选择 3×3 单元格区域后 copy 内容正确。

## 四、阶段二：文档与数据 IO（P0/P1）

> 目标：达成用户核心诉求——**读取其他系统上 SciDAVis 导出的文档**，并能保存回去。

### F-07 系统文件选择器集成 — P0

- **描述与预期行为**：File ▸ Open / Save As / Import / Export 全部通过 ArkTS `@ohos.file.picker`（DocumentViewPicker）选取或指定路径；打开流程 = picker 选文件 → 拷贝到应用沙箱 `filesDir` → 沙箱路径传给 Qt；保存流程 = Qt 写沙箱临时文件 → picker 指定目标 → 拷出。
- **关键挑战**：约束 C7 沙箱模型；URI→fd→沙箱路径的转换（`fs.copyFile`）；大文件拷贝需异步 + 进度提示；picker 回调为异步，需防御性 try-catch（规范 01）。
- **依赖**：无（独立 ArkTS 能力）；被 F-08/F-09/F-10/F-11/F-18/F-31 依赖。
- **验证标准**：从"文件管理"应用可见的任意目录选取一个 .txt 文件，hilog 打印出沙箱内可读路径且 Qt 端 `QFile::exists` 为 true；反向导出文件后能在文件管理中找到。

### F-08 项目打开（.sciprj / .sciprj.gz） — P0 ⭐格式兼容性核心

- **描述与预期行为**:在 Windows/macOS 版 SciDAVis 保存的项目文件（XML 格式 `.sciprj`，及 gzip 压缩 `.sciprj.gz`；含旧版 0.2.4 格式）在鸿蒙版中完整打开：所有 Table（数据、列类型、公式）、Graph（曲线、样式、坐标轴）、Matrix、Note、文件夹结构全部还原。
- **关键挑战**：新增 `openProject` 命令调用 `ApplicationWindow::open(fn)`；**打开过程中 Qt 可能弹版本警告/损坏提示 QMessageBox → 约束 C1 崩溃**，必须预先静默这些交互路径（如设置 `d_inform_rename_table=false` 类开关或捕获后改走日志）；大项目加载耗时 > C2 的 3s 查询超时，openProject 必须按变更命令 fire-and-forget 处理，ArkTS 轮询 `getProjectState` 直到 ready；加载完成后 ArkTS 需全量刷新窗口列表/表格/图表。
- **依赖**：F-07（文件选择器）、F-03（窗口列表刷新）。
- **验证标准**：准备 3 个基准项目文件（Windows 版导出：①纯表格 ②表格+2D 图 ③含公式列与多文件夹），逐个打开后 `getTableData` 数值与源端 100% 一致、`getPlotList` 曲线数一致、无崩溃无 appfreeze。基准文件入库 `test/fixtures/`。
- **备注**：这是格式兼容性的最高优先事项，建议在阶段二最先投入。

### F-09 项目保存 / 另存为 — P0 ⭐格式兼容性核心

- **描述与预期行为**：File ▸ Save / Save As 将当前项目序列化为 `.sciprj`（可选 gzip），保存的文件在 Windows/macOS 版可无损打开（双向兼容）。修改未保存时窗口标题显示 `*`，退出前 ArkTS 弹确认对话框。
- **关键挑战**：新增 `saveProject`/`saveProjectAs` 命令调用 `ApplicationWindow::saveProject()`；Qt 端保存路径必须在沙箱内再由 ArkTS 拷出（F-07 反向流）；"未保存修改"状态需新增 `isProjectModified` 查询；避免 Qt 侧任何保存确认弹窗（C1）。
- **依赖**：F-07、F-08（格式往返测试需先能打开）。
- **验证标准**：鸿蒙版新建表格+录入数据+保存 → 文件拷到 Windows 版打开数据一致；Windows 项目 → 鸿蒙打开 → 修改 → 保存 → Windows 再打开，往返无损（roundtrip 测试）。

### F-10 ASCII/CSV 导入完善 — P1

- **描述与预期行为**：`ImportDialog.ets` 提供与桌面版 Import ASCII 对话框一致的参数：分隔符（Tab/逗号/分号/空格/自定义）、忽略首行数、首行作列名、去空格、数字 locale（点/逗号小数）、导入模式（新表/追加行/追加列/覆盖）；带前 20 行预览。
- **关键挑战**：命令 `importASCII` 已存在，主要工作在 ArkTS：预览需 ArkTS 直接读沙箱文件前 N 行解析（不经 Qt）；locale 参数与桌面版语义对齐。
- **依赖**：F-07。
- **验证标准**：同一 CSV（含逗号小数、表头、5000 行）在 Windows 版与鸿蒙版用相同参数导入，`getTableData` 抽样 100 单元格完全一致；导入 5000 行耗时 < 5s。

### F-11 ASCII/CSV 导出完善 — P1

- **描述与预期行为**：`ExportDialog.ets` 参数对齐桌面版：分隔符、是否含列名、是否仅导出选区、导出全部表/当前表；导出后可经 picker 存到公共目录或分享。
- **关键挑战**：`exportASCII` 已有但写死沙箱路径，需返回实际文件路径供 ArkTS 拷出；选区导出需新增选区参数。
- **依赖**：F-07、F-13（选区）。
- **验证标准**：导出文件在 Windows 版 SciDAVis / Excel 中打开数据一致；1 万行导出 < 5s。

### F-12 最近文件列表 — P2

- **描述与预期行为**：File ▸ Recent Projects 显示最近 10 个项目，点击直接打开。
- **关键挑战**：沙箱拷贝模式下"原始 URI"需 ArkTS 用 `PersistentStorage` 记录并申请持久化 URI 授权（`fileShare` 授权可能受限，降级方案：仅记录沙箱副本）。
- **依赖**：F-08。
- **验证标准**：打开 3 个项目后重启应用，列表保留且逐项可打开。

## 五、阶段三：表格与图表核心功能（P1）

> 目标：完成"数据 → 图"的主工作流，这是 SciDAVis 的产品灵魂。

### F-13 表格编辑完善 — P1

- **描述与预期行为**：对齐桌面版 Table 菜单能力：增删行列、行列数设置、列重命名、列类型（Numeric/Text/Date/Time/Month/Day）与格式（小数位）、列职责（X/Y/Z/X-error/Y-error/None）、选区（单元格/整行/整列/矩形区域）、选区 cut/copy/paste/clear、行列统计入口。`DataTable.ets` 需要虚拟滚动支撑万行级数据。
- **关键挑战**：新增命令组 `tableSetSize/insertRows/insertCols/removeRows/removeCols/setColName/setColType/setColPlotDesignation/getSelection 等`（全部走 C2 fire-and-forget + 查询刷新模式）；选区状态放 ArkTS 侧管理、执行操作时随参数传给 Qt；DataTable 虚拟化性能（LazyForEach）。
- **依赖**：F-05（单元格编辑）、F-06（拖拽选区）。
- **验证标准**：100 列 × 10000 行表格滚动流畅（帧率 ≥ 30fps）；列类型改 Date 后显示格式与桌面版一致；矩形选区复制→粘贴到另一表格数值正确。

### F-14 列公式计算（muParser） — P1

- **描述与预期行为**：Table ▸ Set Column Values：对选中列输入公式（如 `col("A")*2 + sin(i)`），指定行范围求值；快捷入口 Fill with Row Numbers / Random Values / Normal Random。公式语法与桌面版 muParser 完全一致。
- **关键挑战**：新增 `setColumnFormula` 命令（调用 Table 的 muParser 求值路径）；公式错误信息需 JSON 返回给 ArkTS 展示（不允许 Qt 弹错误框，C1）；公式编辑对话框 ArkTS 实现（含函数列表参考面板）。
- **依赖**：F-13、F-05。
- **验证标准**：与 Windows 版对同一表执行同一公式，结果列逐值一致（浮点容差 1e-12）；非法公式返回可读错误不崩溃。

### F-15 2D 绘图创建 — P1

- **描述与预期行为**：选中表格列 → Plot 菜单/工具栏选择图型 → 生成图窗口。首批图型：Line、Scatter、Line+Symbol、Vertical/Horizontal Bars、Area、Histogram、Pie；含误差棒（需 error 列）。多列同时选中生成多曲线。
- **关键挑战**：新增 `createPlot` 命令（参数：tableId、列列表、plotType，调用 `ApplicationWindow::multilayerPlot` 家族）；列职责（X/Y/error）与桌面版取列规则一致；创建后触发 F-16 的刷新链。
- **依赖**：F-13（选区/列职责）、F-16（否则画了看不见）。
- **验证标准**：对同一数据集，8 种图型逐一创建，`getPlotList` 曲线数/类型正确；与 Windows 版同数据同图型截图对比形态一致。

### F-16 图表显示与刷新 — P0 ⭐本阶段最大技术风险

- **描述与预期行为**：图表在内容区正确显示，数据/样式变更后自动刷新，支持缩放平移查看。
- **关键挑战**：两条技术路线需先做 1 天 spike 决策：
  - **路线 A（推荐先验证）— Qt 离屏渲染位图**：新增 `renderPlot` 命令，Qt 端 `MultiLayer` grab 到 QImage → PNG 写沙箱 → ArkTS `Image` 组件显示。优点：渲染 100% 与桌面版一致（坐标轴/图例/字体）；缺点：交互需坐标回传、刷新有延迟（需压到 <100ms）。
  - **路线 B — ArkTS Canvas 重绘**：走现有 `getPlotData` + `PlotCanvas.ets` 自绘。优点：交互流畅；缺点：坐标轴刻度、图例、样式复刻工作量巨大且永远存在视觉偏差，**违背"忠实复现"原则**。
  - 决策标准：路线 A 若单帧渲染 ≤ 100ms 且内存稳定，则 A 为主、B 仅作缩略图。
- **依赖**：F-15；被 F-17/F-18/F-23 依赖。
- **验证标准**：创建图后 1s 内显示；`setCellValue` 改数据后图 1s 内刷新；连续刷新 100 次内存增长 < 10MB；渲染结果与 Windows 版同项目截图逐像素形态一致。

### F-17 图表编辑 — P1

- **描述与预期行为**：双击图表各区域打开对应 ArkTS 编辑对话框（复刻桌面版）：坐标轴（范围/刻度/线性-对数/标题）、曲线样式（颜色/线型/符号）、图例（文本/位置）、图表标题、网格线。
- **关键挑战**：命令组 `setAxisScale/setAxisTitle/setCurveStyle/setLegend/setPlotTitle`（调用 Graph 对应 API）；双击命中区域判定需 Qt 端回传点击元素类型（新增 `hitTestPlot` 查询）；每次修改后触发 F-16 重渲染。
- **依赖**：F-16、F-06（双击）。
- **验证标准**：改轴范围/对数轴/曲线颜色后重渲染结果与 Windows 版同操作一致；对话框字段与桌面版逐项对照无缺失（允许分批实现，每批记录差异清单）。

### F-18 图表导出（PNG/SVG/PDF） — P1 ⭐格式兼容性

- **描述与预期行为**：File ▸ Export Graph：当前图导出 PNG（可设分辨率）、SVG、PDF、EPS，文件经 picker 存到公共目录，可直接用于论文/报告。
- **关键挑战**：新增 `exportPlot` 命令（复用 `MultiLayer::exportImage/exportVector`）；Qt 无 GUI 打印上下文时 PDF/EPS 导出的可行性需真机验证（QPrinter 依赖），不可行则降级 PNG/SVG。
- **依赖**：F-16、F-07。
- **验证标准**：导出的 PNG/SVG 在 PC 端打开与 Windows 版导出视觉一致；SVG 文本可编辑。

### F-19 矩阵窗口 — P2

- **描述与预期行为**：Matrix 的查看/编辑（数值网格、维度设置、公式填充）、矩阵↔表格转换、3D 图数据源。
- **关键挑战**：命令组 `getMatrixList/getMatrixData/setMatrixCell/setMatrixDimensions/setMatrixFormula`；复用 DataTable 组件渲染。
- **依赖**：F-13 组件、F-05。
- **验证标准**：含矩阵的 Windows 项目打开后矩阵数据一致；编辑保存往返无损。

### F-20 笔记窗口（Notes） — P2

- **描述与预期行为**：多行文本笔记的编辑与保存（`NoteEditor.ets` 已有雏形），随项目持久化。
- **关键挑战**：新增 `getNoteText/setNoteText` 命令；中文/长文本 IME 稳定性（C3）。muParser 脚本执行（Execute）延后到 F-32 范围。
- **依赖**：F-05、F-03。
- **验证标准**：2000 字中英混排笔记保存→重开项目内容无损；Windows 版打开显示一致。

## 六、阶段四：数据分析计算（P1/P2）

> 计算全部在 Qt/GSL 端完成（引擎现成），工作量集中在 ①命令封装 ②ArkTS 参数对话框 ③结果展示。
> 统一模式：ArkTS 对话框收集参数 → `callQtCommand` → Qt 执行并写 Results Log/生成结果表格或曲线 → ArkTS 拉取刷新（F-04/F-16 链路）。

### F-21 列/行统计 — P1

- **描述**：Statistics on Columns/Rows：对选区生成统计表（行数/均值/标准差/方差/和/最大/最小）。
- **挑战**：新增 `colStatistics/rowStatistics` 命令（调用 `ApplicationWindow::showColStatistics` 的无 UI 路径）；结果以新表格窗口出现。
- **依赖**：F-13（选区）、F-03（结果窗口）。
- **验证**：与 Windows 版同数据统计值逐项一致（容差 1e-12）。

### F-22 排序 / 归一化 — P1

- **描述**：单列/多列排序（升/降、以某列为主键）、列归一化（除以最大值）、表归一化。
- **挑战**：命令 `sortColumns/normalize`；排序参数对话框 ArkTS 化。
- **依赖**：F-13。
- **验证**：排序后 `getTableData` 与 Windows 版一致；撤销可恢复（F-27）。

### F-23 曲线拟合 — P1 ⭐分析功能旗舰

- **描述**：Analysis ▸ Fit：线性、多项式（可选阶数）、指数、Gaussian、Lorentzian、非线性自定义公式拟合（GSL Levenberg-Marquardt）、多峰拟合。拟合结果曲线叠加到原图、参数与卡方写入 Results Log。Fit Wizard 对话框 ArkTS 复刻（公式、初值、迭代数、算法选择）。
- **挑战**：命令组 `fitLinear/fitPolynomial/fitNL(formula, initialGuess[], ...)`（复用 `Fit` 类家族）；拟合是长任务，走 fire-and-forget + `getFitStatus` 轮询；初值不当导致 GSL 不收敛的错误须 JSON 化返回（C1）。
- **依赖**：F-16（结果曲线显示）、F-04（报告展示）、F-15。
- **验证**：标准数据集（如高斯峰+噪声）拟合参数与 Windows 版差异 < 0.1%；不收敛场景给出与桌面版等价的提示。

### F-24 FFT / 滤波 — P2

- **描述**：正/逆 FFT（生成幅频/相频表格与图）、低通/高通/带通/带阻滤波。
- **挑战**：命令 `fft/filter`（复用 `FFT`/`FFTFilter` 类）；参数对话框（采样间隔、窗函数）。
- **依赖**：F-15/F-16、F-21 模式。
- **验证**：标准正弦叠加信号 FFT 峰值频率与 Windows 版一致。

### F-25 插值 / 平滑 / 微积分 — P2

- **描述**：插值（线性/三次/Akima）、平滑（移动窗口/Savitzky-Golay/FFT）、数值微分、数值积分。
- **挑战**：命令封装（`Interpolation/SmoothFilter/Differentiation/Integration` 类现成）；各自小参数对话框。
- **依赖**：同 F-24。
- **验证**：结果曲线数据与 Windows 版一致（容差 1e-9）。

### F-26 相关 / 卷积 — P2

- **描述**：自相关、互相关、卷积、反卷积（双列输入 → 结果表+图）。
- **挑战**：命令封装（`Correlation/Convolution` 类）；双列选择 UI。
- **依赖**：同 F-24。
- **验证**：与 Windows 版结果一致。

### F-27 撤销/重做完整性 — P1

- **描述**：所有经命令通道的数据变更均可 undo/redo，深度与桌面版一致；工具栏按钮随可撤销状态启用/禁用。

- **依赖**：无强依赖。

### F-29 多语言一致性 — P2

- **描述**：ArkTS 层全部字符串走 `$r('app.string.*')` 资源（规范 07），中英双语与桌面版 .ts 翻译一致。
- **挑战**：从 `scidavis/translations/*.ts` 批量提取术语映射到 ArkTS 资源，保证菜单术语与桌面中文版一字不差。
- **依赖**：F-01/F-02（文案载体）。
- **验证**：系统切中/英文后全 UI 无硬编码残留（grep 校验 + 截图对比）。

### F-30 3D 绘图 — P3

- **描述**：矩阵/公式 3D 表面图、散点、轨迹（桌面版基于 QwtPlot3D/OpenGL）。
- **挑战**：QwtPlot3D 依赖 OpenGL 上下文，QPA 离屏 GL 可行性完全未知——先做可行性 spike：不可行则降级为"打开含 3D 图的项目不崩溃、显示占位图并保留数据"（保存往返不丢 3D 图定义）。
- **依赖**：F-16 路线 A、F-19。
- **验证**：最低标准 = 含 3D 图项目打开/保存无损不崩溃；理想标准 = 静态渲染显示。

### F-31 Origin .opj / QtiPlot .qti 导入 — P3

- **描述**：File ▸ Import：读取 OriginLab .opj（liborigin）与 QtiPlot .qti 项目。
- **挑战**：确认 liborigin 已随 OHOS 交叉编译进 libentry.so（`llvm-nm` 验证符号）；新增 `importOpj` 命令；异常 .opj 文件的容错（禁止弹窗，C1）。

## 十、给 AI 助手的执行指令摘要

1. **逐功能推进**，严格按本文档编号顺序（允许同阶段内并行无依赖项）；开工前重读对应功能块与 §1.3 硬约束。
2. **扩展命令通道** 是绝大多数功能的核心动作：Qt 侧改动限定在 `scidavis/src/main.cpp` 的 `scidavis_call` 分发器内新增 `else if` 分支 + 静态辅助函数（须用户对该文件授权）；禁止改动 `libscidavis` 核心类。
3. **变更命令一律 fire-and-forget**（C2），UI 刷新用后续查询命令拉取；查询命令保持只读、不触碰 QPA 回调。
4. **任何对话框都在 ArkTS 实现**（C1），Qt 侧凡可能弹窗的 API 调用前必须排查并绕过。
5. **每次修改走完整闭环**（§1.4），未经真机验证不得标记功能完成。
6. 疑难 ArkTS 语法/ArkUI 规范问题按 HARNESS_AI_GUIDE §五 决策树委派 `deveco run`。
7. 未列入本计划的行为差异或新发现约束，追加记录到本文档 §1.3 并同步 `docs/` 相关文档。
