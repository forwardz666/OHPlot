# UI 缩放实现规范

## 一、SciDAVis OpenHarmony UI 缩放（Qt 方案）

**核心原则：** UI 缩放必须通过 **Qt 环境变量** 调整，**禁止重写前端**。

### 1.1 Qt 环境变量缩放
使用 `QT_SCALE_FACTOR` 环境变量控制全局缩放：
```bash
# 构建前设置缩放因子
set QT_SCALE_FACTOR=1.5
# 或在代码中通过 qputenv 设置
qputenv("QT_SCALE_FACTOR", "1.5");
```

### 1.2 缩放目标
- 目标：恢复到初始适配时的视觉尺寸
- 当前问题：界面过小需放大
- 通过调整 `QT_SCALE_FACTOR` 值直到视觉匹配

### 1.3 排查优先级
当 UI 尺寸异常时，按以下顺序排查：
1. 检查 `QT_SCALE_FACTOR` 等 Qt 环境变量配置
2. 检查 Qt 高 DPI 缩放策略（`Qt::AA_EnableHighDpiScaling`）
3. 检查系统显示设置

### 1.4 禁止事项
- 禁止为缩放目的重写前端 ArkTS 布局
- 禁止在 CSS/ArkUI 层面做全局缩放补偿

---

## 二、前端 UI 缩放技术参考（Web 场景）

当涉及前端（Web/ArkUI CSS）缩放实现时的建议：

1. **推荐方案：** 使用 `transform: scale()` 或 `zoom` 属性作用于根容器（`#root` 或 `body`）
2. **布局检查：** 检查 scripting 面板的 flex/grid 布局，确保 `min-width` 和 `overflow` 设置合理，防止文字被截断
3. **注意事项：**
   - `transform: scale()` 不会改变布局尺寸，仅视觉缩放
   - `zoom` 会同时改变视觉和布局尺寸
   - 选择方案需根据场景需求决定
