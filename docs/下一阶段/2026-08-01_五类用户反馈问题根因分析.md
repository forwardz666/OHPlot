## 问题 1：表格交互（拖拽/全屏/选中/输入/侧边栏）

### 1.1 根因分析

| 子项 | 根因 | 证据 |
|------|------|------|
| 表格无法选中/输入 | 表格渲染在 XComponent（Qt 侧）。内容区默认 `HitTestMode.Transparent` 透传给 Qt（MainLayout.ets:977-986），触摸由外层 Stack `onTouch` → `sendMouse` 转发（MainLayout.ets:1213-1277）。**但工具栏/菜单栏区带（topChromeVp）被硬编码拦截**（MainLayout.ets:1228-1230），若 Qt MDI 区域因 setChromeInsets top 偏小被覆盖层遮挡（问题3），表格首行/输入区不可点 | 问题3 联动 |
| 表格无法拖拽 | Qt 表格拖拽需鼠标 Move 事件连续注入。当前 `sendMouse` 在 touch Move 时转发（MainLayout.ets:1255-1257），但依赖 `leftDown` 标志；若 Up 事件丢失（band guard），状态卡死 | MainLayout.ets:1224-1254 |
| 侧边栏消失 | `ColumnSidebar` 数据来自 `getColumnInfo` 命令；若 activeType 判断（Table）或表格未激活，侧边栏不显示；且 `description` 等字段依赖 Qt 返回列属性 | ColumnSidebar.ets 调研 |
| 无法全屏 | Qt 窗口全屏依赖 `maximize_window` 命令（已在 MENU_ACTION_SUPPORTED 白名单）；但无对应 ArkTS UI 入口（问题5 关联） | MainLayout.ets:79-84 |

### 1.2 修复方向
1. **问题3 修复后**（top 对齐）→ 表格首行可点、可输入、可选中；
2. `sendMouse` 的 `leftDown` 状态机加超时兜底（防 Up 丢失卡死）；
3. ColumnSidebar 补充 activeType/表格激活校验日志，确认数据流。

## 问题 2：新建矩阵/注释/图形失灵

### 2.1 根因

`menuAction` 命令（main.cpp:1442-1527）处理 `new_notes/new_matrix/new_graph`：

| 命令 | Qt 调用 | 问题 |
|------|---------|------|
| `new_matrix` | `g_mainWindow->newMatrix()`（默认 32x32） | **`newMatrix(int rows=32,int columns=32)` 创建矩阵后只 `d_project->addChild`，没有 `d_workspace.addSubWindow` + `showNormal()`**（ApplicationWindow.cpp:2599-2609）→ 矩阵创建但**不可见** |
| `new_notes` | `g_mainWindow->newNote()` | `newNote()` 有 `addSubWindow` + `showNormal()`（ApplicationWindow.cpp:2563-2572）→ 理论上正常，需真机确认 |
| `new_graph` | `g_mainWindow->newGraph()` | `newGraph()` → `multilayerPlot()` 创建 MultiLayer；需确认是否显示（内部 initMultilayerPlot 应有 addSubWindow） |

**关键证据**（ApplicationWindow.cpp:2599-2609）：
```cpp
Matrix *ApplicationWindow::newMatrix(int rows, int columns) {
    Matrix *m = new Matrix(scriptEnv, rows, columns, "", 0, 0);
    QString caption = generateUniqueName(tr("Matrix"));
    while (alreadyUsedName(caption)) caption = generateUniqueName(tr("Matrix"));
    m->setName(caption);
    d_project->addChild(m->d_future_matrix);   // ← 只有这一行，无 addSubWindow/showNormal
    return m;
}
```

### 2.2 修复方向
- 新增专用命令（如 `newMatrix`）在 main.cpp 注册表：调用 `newMatrix(32,32)` 后补 `d_workspace.addSubWindow` + `showNormal()`（对照 newNote 的实现），或在 menuAction 的 `new_matrix` 分支内补显示逻辑；
- new_notes/new_graph 真机验证，若同样不显示则一并补。

## 问题 3：Qt 窗口顶部与 ArkTS 覆盖层对齐

### 3.1 根因

- ArkTS 侧 `pushChromeInsets()`（MainLayout.ets:306-320）计算 `top = vp2px(topChromeVp())`，其中 `topChromeVp() = MENUBAR_HEIGHT_VP(28) + toolbarHeightVp(动态)`（MainLayout.ets:298-300）；
- Qt 侧 `setChromeInsets`（main.cpp:1640-1650）`centralWidget()->setContentsMargins(0, top, 0, bottom)`；
- **若 vp2px 换算密度与实际不符，或 toolbarHeightVp 测量滞后/未推送**，Qt MDI 区域顶部与 ArkTS 覆盖层底部不对齐 → 覆盖层遮挡表格/矩阵首行。

### 3.2 需要验证
1. `vp2px` 实际换算（设备 DPR 2.2，见日志 `GetVirtualPixelRatio: 2.200000`）；
2. `toolbarHeightVp` 初始值 32 与真实工具栏高度是否一致、`onAreaChange` 是否及时推送；
3. 真机截图对比 ArkTS 覆盖层底部与 Qt 窗口首行。

### 3.3 修复方向
- 核对 `vp2px(topChromeVp())` 计算：物理像素 = vp × DPR（2.2），确认 Qt 侧收到正确值；
- 若 toolbarHeightVp 初始值不准，改用固定常量 + onAreaChange 校正双保险；
- 在 `setChromeInsets` 调用链增加日志输出 top 值，真机核对。

## 问题 4：右键菜单

### 4a. Qt 渲染窗口右键只在固定位置弹窗

**根因（已确认）**：`ContextMenu.ets:21-22`：
```typescript
@State positionX: number = 0;
@State positionY: number = 0;
```
`@State` 是组件**内部状态**，父组件（MainLayout）传入 `positionX: this.contextMenuX` 只初始化一次，后续 `contextMenuX` 变化**不会**传导到子组件 `@State`。因此右键后 `contextMenuX/Y` 更新了，但 ContextMenu 内部始终是初始值 (0,0) → 菜单位置固定。

**修复**：改为 `@Prop`（单向，够用）或 `@Link`：
```typescript
@Prop positionX: number = 0;  // 或 @Link positionX: number
@Prop positionY: number = 0;
```

### 4b. ArkTS 图标功能栏右键彻底失灵

**根因（已确认）**：`ToolBar.ets` 按钮只有 `.onClick`/`.onHover`（L143/162/186），**无 `.onMouse`** → 右键无处理器。

**修复**：ToolBar 按钮/容器增加 `.onMouse`，右键时回调（如复用 onItemClick 或显示上下文菜单）。

## 问题 5：最大化后 min/max/close 三键

### 5.1 根因
- 表格/矩阵是 Qt MDI 子窗口；最大化后 Qt 侧渲染 MDI 标题栏按钮（min/max/close），但其位置在 Qt 窗口内部，与 ArkTS "files" 菜单行（覆盖层顶部）不对齐；
- Windows 版 scidavis：MDI 子窗口最大化后，窗口控制按钮显示在主菜单行最右端（与 File 菜单同行）。

### 5.2 修复方向（借鉴 Windows 版）
- **方案 A（推荐）**：ArkTS 覆盖层顶部（MenuBar 行最右端）新增 min/max/close 三个按钮，点击调 `menuAction('maximize_window'/'minimize_window'/'close_window')`（已在白名单）；最大化时高亮 max 键；
- **方案 B**：调整 Qt MDI 区域 insets 使标题栏与覆盖层对齐（复杂，易引入回归）。
