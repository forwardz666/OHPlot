## 1. 备份策略（先行，贯穿全程）

### 1.1 现状盘点（2026-07-31 实测）

- git 仓库：`ohos/` 为独立 git 仓库，当前分支 `main`，**存在未提交变更**（docs 目录整理中，staged 状态）；
- 现有备份约定：`scidavis-ohos/backup-YYYYMMDD-HHMMSS/*.bak` + `scidavis-ohos/backups/`；
- libs 目录由 `scripts/deploy-libs.sh` 填充（README 注明勿手工维护）——**此脚本会覆盖手工替换的插件，P0 必须同步处理（见 P0-6）**；

## 2. P0：QPA 插件升级 + 官方启动流程

### 2.1 目标

用 AirStars 同款新版 QPA 插件（支持 `attachAbilityStage`）替换当前 alpha_v6 插件，
将 Qt 启动从"自定义 C++ 线程 + dlopen/dlsym"切换到官方 `attachAbilityStage + startQtApplication(this)` 流程，
消除 qohos.cpp 中约 200 行自研启动代码与 TSFN 死锁规避逻辑。

### 2.2 关键事实（二进制符号级证据，2026-07-31 实测）

| 符号 | 当前插件 alpha_v6 (1.36MB) | AirStars 新版 (3.22MB) |
|------|---------------------------|------------------------|
| `attachAbilityStage` | ✗ | ✓ |
| `startQtApplication` | ✓ `(dirs, appBinary)` | ✓ `(this)` |
| `launchApplication/launchParams/launchWant`（ability 属性） | ✗ | ✓ |
| `setDeviceType/setDisplayMetrics/setDefaultShowIsMaximized/setResourceManager/setDisplayVersion/setFontInfos/setTouchPad/setJsQuitFunction` | ✓ | ✗ |
| `qtMajorVersion/quitQtApplication` | ✓ | ✗ |
| `g_xcomponentMode`（应用导出，供插件选事件循环模式） | 未用 | 应用导出 |

> **推论**：新插件不再接受旧的 setter 式配置，改为从 ability 上下文自取。
> **⚠ 审查关键意见**：`setJsQuitFunction`、`qtMajorVersion` 当前代码均在调用（OHPlotAbility.ets:272、:357），
> 若新插件真无此二 API，直接删除/调用会分别导致 **bootstrap 中断** 与 **JS 桥永不注册（假阴性）**。
> 因此 P0-3 采用**能力探测 + 条件调用**策略（见 2.4），而非一刀切删除。

### 2.3 新插件启动链路（参照 AirStars 实测代码）

```
MyAbilityStage.onCreate
  → qpa.attachAbilityStage(this)              // 早期上下文绑定，防 napi_env 错乱
EntryAbility.onCreate
  → 设置 ability 属性：launchApplication='libentry.so'、launchParams、launchWant=原始want
  → want.parameters 注入实验参数（黑屏修复三件套）
  → entry.preloadLibs()  +  entry.getQpa()    // dlopen 链 + 插件 NAPI 模块加载
EntryAbility.onWindowStageCreate
  → 全屏 + 系统栏处理
  → qpa.startQtApplication(this)              // 插件读 ability 属性 dlopen → main()
```

### 2.4 实施步骤（v2 重排：**先换插件，再改代码**）

> v2 修正：原 v1 将 MyAbilityStage 改动（P0-1）放在换插件（P0-2）之前，导致该步在旧插件上
> 无法通过验收（旧插件无 attachAbilityStage），且提前在 AbilityStage 导入 QPA 正是现有
> MyAbilityStage.ets 头部注释警告的 SIGSEGV 风险源。故重排。

| 步骤 | 文件 | 改动内容 | 验证 |
|------|------|---------|------|
| **P0-1** | `entry/libs/arm64-v8a/libplugins_platforms_qopenharmony.so` | ① 备份旧插件（B7）；② 复制 AirStars 版插件（3.22MB）→ `binary-sign-tool -selfSign 1` → 重打包 HAP → 真机安装 | 安装成功，应用可启动（旧代码暂不依赖新 API，应无回归） |
| **P0-2** | `entry/src/main/ets/abilitystage/MyAbilityStage.ets` | ① 更新文件头部 NOTE 注释（标注：alpha_v6 时代的 napi_env 警告已随插件升级解除，若回退到 alpha_v6 须恢复该警告）；② `import qpa from 'libplugins_platforms_qopenharmony.so'`；③ `onCreate` 内 try-catch 调 `qpa.attachAbilityStage(this)`（对照 AirStars 24 行文件） | 日志出现 `attachAbilityStage called`；无 SIGSEGV |
| **P0-3** | `entry/src/main/ets/entryability/OHPlotAbility.ets` | ① 重写 `QpaModule` 接口：仅保留新插件确认存在的符号（attachAbilityStage 在 stage 侧、startQtApplication(this)、handleGeometryChange、handleWindowEvent），setter/旧方法从接口移除；② **能力探测替换**：`const has = (k) => typeof (qpa as any)[k] === 'function'`，对 setJsQuitFunction/qtMajorVersion/quitQtApplication 等不确定符号**条件调用**（存在才调，不存在记日志），杜绝未定义调用抛错中断 bootstrap；③ 删除 setter 调用块（`setDeviceType`→`setTouchPad` 约 25 行，含字体枚举逻辑——字体改由新插件自取，见 V0-8 字体验证）；④ 新增 ability 属性 `launchApplication='libentry.so'`、`launchParams`、`launchWant=原始want`（保存原始 want 对象）；⑤ 注入实验参数 `io.qt.experimental.enableGlBackingStore=false`、`enableVsyncOnSoftwareBackingStore=false`、`enableSwapBufferSync=false` 到 want.parameters；⑥ 启动调用改为 `qpa.startQtApplication(this)`，**保留 `if (!qtStarted)` 回退到 `qohos.startQtNative` 的分支**（回退通道不删）；⑦ `initQtBridge` 中 `qtMajorVersion()` 条件调用（存在才用，否则跳过版本分支）；⑧ Qt 退出行为：`setJsQuitFunction` 若不存在，改用 `onWindowStageDestroy`/监听替代，或保留 quitQtApplication 条件调用 | 见 §2.5 验证矩阵 |
| **P0-4** | `entry/src/main/ets/pages/Index.ets` | XComponent 从 `SURFACE` 迁移到 `NODE` 类型（新插件按 AirStars 用 NODE；**若 SURFACE 仍可用则跳过**，先验证再迁） | Qt 窗口正常渲染；截图入 `diagnostics/` |
| **P0-5** | `qohos.cpp` / `scidavis/src/main.cpp` / `CMakeLists.txt` | ① **暂不删除** qohos.cpp 的 startQtNative，保留回退；② 确认 libentry.so 是否导出 `extern "C" bool g_xcomponentMode`——如新插件按 AirStars 需它来选择事件循环模式，则在 `scidavis/src/main.cpp` 增加导出（B10 已备份），并重建 libentry.so | `nm -D libentry.so` 可见 g_xcomponentMode；回退通道可用 |
| **P0-6** | `scripts/deploy-libs.sh` | 把新插件纳入 deploy 源，或将 QPA 插件加入排除清单（不覆盖手工放置的版本）——**否则下次运行 deploy-libs.sh 会把插件刷回 alpha_v6，P0 变更不持久** | 重新运行 deploy-libs.sh 后插件仍为 3.22MB 新版 |

### 2.5 JS 桥兼容性验证（P0 最大不确定点，V0 关卡）

新插件被证明对 QML 应用有效，但 scidavis 是 **Widgets 应用 + 6 个 JS 桥对象**，
新插件是否仍走 `createJsObject` TSFN 通道**必须真机验证**：

| 验证项 | 方法 | 通过标准 |
|--------|------|---------|
| V0-1 桥请求 | 启动日志 grep `request js object` | 出现 `JsLocale`（或新插件对应机制） |
| V0-2 桥返回 | 日志 grep `createJsObject ... → ok` | 6 个对象至少 JsLocale/JsStandardPaths 返回 ok |
| V0-3 启动稳定性 | 连续启动 3 次 | 无 SIGSEGV / 无 `QOpenHarmonyJsObject NULL` |
| V0-4 事件循环 | 日志 heartbeat #1~#10 | 事件循环存活 |
| V0-5 鼠标注入 | 覆盖层点击 → InputProbe 日志 | `mouse press recv=` 正常 |
| V0-6 键盘 | 蓝牙键盘输入符号键 | `symbolShift[]` 合成正确 |
| V0-7 Qt→ArkTS 事件 | 触发 Qt 弹窗 | `scidavis_emit → TSFN → ArkUI 弹窗` 链路通 |
| V0-8 字体 | 真机截图对比面板文字 | 字号/字体与升级前一致（新插件自取字体路径正确） |
| V0-9 Qt 退出 | 菜单 File→Exit | 应用进程被杀，无僵尸残留（quit 替代机制生效） |
| V0-10 多实例 | 连续两次启动 | onAcceptWant instanceKey 逻辑不受 attachAbilityStage 影响 |

**若 V0-1/V0-2 失败**（新插件不兼容 Widgets 桥）→ **回退**（§1.3 P0 出口），
记录结论到 AGENTS.md，保留现有 C++ 线程方案，等待插件继续演进。

## 3. P1：低风险借鉴项（不依赖 P0，可并行先行）

### 3.1 qt.conf 生成（AirStars `napi_init.cpp` 41-49 行）

- **位置**：`qohos.cpp` `SetupQtEnv()` 内追加独立函数 `WriteQtConf()`；
- **内容**：写入 **`<bundleCodeDir>/libs/arm64/qt.conf`**（与 libentry.so 同目录，Qt 才可能读取；v2 修正：不写入 cacheDir/filesDir）：
  ```
  [Paths]
  Plugins = <bundleCodeDir>/libs/arm64
  ```
- **验证**：① 文件存在且路径正确；② 与 `QT_QPA_PLATFORM_PLUGIN_PATH` 环境变量互为冗余，插件加载无 warning（注意：若 Qt 实际不读该位置，此条为无害冗余，靠环境变量兜底）。

### 3.2 显式 `QT_QPA_PLATFORM=openharmony`（AirStars `napi_init.cpp` 35 行）

- **位置**：`qohos.cpp` `SetupQtEnv()`；
- **改动**：`setenv("QT_QPA_PLATFORM", "openharmony", 1);`（当前缺失，仅设了 plugin path）；
- **验证**：QPA 插件发现路径无歧义，启动日志明确加载 openharmony 平台。

### 3.3 rawfile 资源落地工具泛化（AirStars `EntryAbility.ets` 43-118 行）

- **现状**：scidavis 仅有 `copyRawTranslations`（硬编码 2 个 .qm）；

  - marker 文件存在则跳过（避免重复拷贝）；
  - `.so` 文件跳过（留在 bundle 供 dlopen，符合鸿蒙安全策略）；
  - 递归目录处理。
- **落地位置**：`entry/src/main/ets/utils/RawfileCopier.ets`（新增）；
- **改造**：OHPlotAbility.ets 的 `copyRawTranslations` 改用该工具（**附录 A 需登记 P1 对 OHPlotAbility.ets 的修改**）；
- **验证**：首次启动拷贝完成、二次启动 marker 命中跳过。

### 3.4 HDS 视效集成（AirStars `managers/HdsVisualManager.ets`，100 行）
