## 工作内容

1. **大面积扫描**（跳出局部）：
   - Table 构造链：newTable() → Table 构造 → init() → setGeometry(0,0,600,400)（所有路径一致）
   - handleAspectAdded（228 行 connect）→ initTable：所有 addChild 都走此路径
   - main.cpp 命令链：newTable 命令（714-722）/new_project 分支（1479-1493）均无最大化操作
   - ArkTS 侧：新建表格（MainLayout:640-642 callQtCommand('newTable')）、新建项目（631 menuAction new_project）均无额外最大化调用
2. **真机诊断实证**：initTable 加 PRE/POST 诊断日志 → 启动 Table1 `PRE geo=600x400 WA_Resized=1`、`POST 600x400` —— **启动路径正确**，新建异常必在激活环节。
3. **根因定位**（Qt 源码级）：QMdiArea::emitWindowActivated（qmdiarea.cpp）：
   ```cpp
   if (showActiveWindowMaximized) {
       if (!activeWindow->isMaximized())
           activeWindow->showMaximized();   // 新激活窗口被最大化
       showActiveWindowMaximized = false;
   }
   ```
   该标志在 setActiveSubWindow 时由"前一个活动窗口 isMaximized && isVisible"设置
   （qmdiarea.cpp:681-683）。ApplicationWindow **未设置** DontMaximizeSubWindowOnActivation →
   新建表格/项目激活时若前一窗口（如用户曾最大化的 Table1）已最大化，则继承最大化。
4. **第一层修复**：ApplicationWindow 构造函数 d_workspace 初始化处（325 行）加：
   `d_workspace.setOption(QMdiArea::DontMaximizeSubWindowOnActivation);`
5. **第二层修复**：`initTable()` 在 `addSubWindow()` 后保存 QMdiArea placer 位置，执行
   `setWindowState(Qt::WindowNoState)` + `setGeometry(placedPos.x(), placedPos.y(), 600, 400)`，
   再 `showNormal()`。曾使用的 queued 强制回调已移除，避免误伤项目/模板恢复的合法尺寸。
6. **构建部署**：libentry.so 重建（14:02:06）→ HAP → 真机部署启动正常。

## 技术决策

- **决策 1**: 保留 Qt 官方选项 `DontMaximizeSubWindowOnActivation`，阻断标准 Qt 激活继承最大化。
- **决策 2**: 在 `initTable()` 的 `addSubWindow()` 后再次强制 normal 和 600x400，覆盖当前 QPA 的后续
  激活/几何时序；保存 placer 的 `pos()`，避免多个表格叠在 (0,0)。
- **决策 3**: 移除 queued 强制回调，避免打开项目/模板时覆盖合法保存几何或最大化状态。
