# 2026-08-02 工作日志：上下工具栏 hover 提示统一（自定义浮层替代 bindPopup）

> 用户反馈：鼠标悬停下方工具栏图标不显示功能提示（上方正常）。排查发现 hover 事件正常触发，
> 但 **bindPopup 的 popup 被 Qt XComponent（native 渲染层）遮挡**（下方 popup 向上弹出到内容区
> = XComponent 区域不可见；上方 popup 弹出到菜单栏区域不受遮挡所以正常）。
> 解决：改用 MainLayout 自定义浮层（zIndex 300 覆盖 XComponent），并**统一上下两行样式**（上方
> 弃用 bindPopup 改用同一浮层）。真机验证全部正常。

---

## 工作内容

1. **现象**：下方 15 个图标（Plot 7 + Plot3D 4 + Table 4）hover 无提示；上方 ToolBar 正常。
2. **诊断**：BottomToolBar 的 onHover+bindPopup 代码与 ToolBar 相同，加临时 hilog 证实
   `[BTB] hover xxx=in/out` **正常触发** → hover 事件没问题，**popup 被遮挡**。
3. **根因**：下方 popup placement=Top 弹出到内容区（Qt XComponent native 渲染层）→ 被盖住；
   上方 popup 弹出到菜单栏区域（纯 ArkUI）→ 可见。
4. **方案 A（下方）**：弃用 bindPopup，改 **MainLayout 自定义浮层**（Stack 顶层 zIndex 300，
   仿窗口控制键层级）——BottomToolBar onHover 时通过 onHoverTip 回调上报 (tipKey, x, y, show)，
   MainLayout 显示黄底黑字 Text 浮层（位置 = 按钮上方 34px）。验证通过。
5. **方案 B（统一）**：用户要求上下样式统一 → ToolBar 也弃用 bindPopup，改同一浮层机制
   （上方浮层显示在按钮下方 30px）。提取 MainLayout `handleHoverTip()` 私有方法供两处复用。
6. **构建部署 + 真机验证：全部正常 ✅**（上下两行提示样式完全一致、位置正确）。

## 技术决策

- **决策 1（浮层替代 popup）**: ArkUI `bindPopup` 无法覆盖 Qt XComponent（native Surface 层级更高）；
  自定义浮层（Stack 顶层 + zIndex 300）可覆盖（窗口控制键同法已验证）。
- **决策 2（统一机制）**: 上下两行共用 MainLayout `handleHoverTip()` + 单浮层；位置差异（上方
  按钮下 30px / 下方按钮上 34px）由各工具栏上报的 y 决定。
- **决策 3（tipKey 传递）**: onHoverTip 上报**按钮的 tip 键名**（tip_plot_area 等），MainLayout
  用 getAppString(tipKey) 解析中文文本——避免 id→键名映射错误。
