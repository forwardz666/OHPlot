## 技术决策

- **决策 1（根因结论）: AirStars QPA 插件与 OpenHarmony 设备不兼容，P0 升级路径排除。**
  证据链：
  1. 新插件 DT_NEEDED 依赖 19 个 HarmonyOS NEXT 系统库（libudmf/libpasteboard/libohinputmethod/libnative_window_manager/libqos 等）；
  2. 真机 `find /system /vendor` 确认这些库**全部缺失**（设备为 OpenHarmony-7.0.0.32, API 26）；
  3. dlopen 失败 → NAPI 模块未注册 → ArkTS `import qpa` 返回 undefined → `attachAbilityStage failed: {}`；
  4. 对照：旧插件 alpha_v6 仅依赖 13 个 OpenHarmony 基础库，工作正常（startQtApplication true + 6 桥 + heartbeat）。
  **含义**：AirStars 用 HarmonyOS NEXT SDK 编译的 Qt 工具链（其 Qt5Core 也无 JS 桥符号）；scidavis 用 OpenHarmony SDK 工具链。两者 Qt 版本号同为 5.15.12 但构建不兼容。
- **决策 2: 保留能力探测（hasFn）作为未来防御性编程参考**，但当前 alpha_v6 插件 setter API 完整，无必要引入。
- **决策 3: 回退采用 .bak + git 双通道**：由于 P0 代码未提交、libs 目录不在 git 跟踪内，回退依赖 B3~B7 备份，验证哈希一致后恢复。
