2. **知识检索**：`@ohos.measure` MeasureOptions 确认——fontFamily 仅支持默认 'HarmonyOS Sans'（显式传入安全且与 Text 渲染一致）；TextOverflow.Ellipsis 必须配合 maxLines 使用（maxLines(1)+textOverflow 为正确防折行兜底）。
3. **根因分析**：
   - 问题 A（折行）：旧 `textWidthVp` 纯 MeasureText px→vp，无 CJK 膨胀，HarmonyOS Sans 中文字形宽度被低估 → 中文最长项（如"更改类型和格式..."、"将列设为..."）在计算宽度下溢出折行；旧宽度只在"菜单含图标项"时才加图标槽，且无安全缓冲。
   - 问题 B（双栏对齐）：旧行渲染 `if (icon) Image else 无`，无图标项文字从 padding 处直接开始，比有图标项靠左 24vp，与 Win SciDAVis 固定图标列布局不符。
4. **实施**（单一文件 MenuBar.ets）：
   - 常量：新增 `ICON_COLUMN_WIDTH=24`、`ICON_SIZE=16`、`ICON_GAP=8`、`PARENT_ARROW_WIDTH=12`、`SAFETY_BUFFER_VP=8`、`CJK_EXTRA_PER_CHAR_VP=2.5`、`CJK_CHAR_RE=/[\u4e00-\u9fff\u3400-\u4dbf\u3040-\u30ff]/`；移除旧 `ICON_SLOT_WIDTH`（hasIcon 条件逻辑一并删除）。
   - `textWidthVp`：measureText 传 `fontFamily: 'HarmonyOS Sans'`；按 CJK 正则逐字计数，每字 +2.5vp 膨胀。
   - `computePanelWidthVp`：每项宽度 = ICON_COLUMN_WIDTH（无条件）+ 标签（checked 时 '✓ ' 前缀）宽度 + 快捷键（SHORTCUT_GAP + 快捷键宽度）+ 父行项 ▸ 箭头宽度；取最大 + PAD_LEFT + PAD_RIGHT + SAFETY_BUFFER_VP。一级与 child 面板共用此函数（childPanelWidthVp 不变，自动获得同宽图标列 + 缓冲）。
   - 行渲染（NormalRow/ParentRow/ChildRow）：`if (icon !== undefined) Image(16×16).margin({right:8}) else Blank().width(ICON_COLUMN_WIDTH)` → 所有行标签起点一致（padding 左 24 + 图标列 24）。
   - PasteRow：保留 PasteButton 授权逻辑，标签 margin 改常量 ICON_GAP（=8，数值不变）；PasteButton 设备实际宽度 >24vp 时标签略偏右属可接受（不 over-engineer）。
   - 全部标签与快捷键 Text 补 `.maxLines(1)` + `.textOverflow({overflow: TextOverflow.Ellipsis})`（ParentRow ▸ 箭头亦加 maxLines(1)）。
5. **验证**：arkts_check 无错误；hvigor 命令行构建 BUILD SUCCESSFUL（17s，仅预存 deprecated WARN，MenuBar 无告警）。

## 技术决策

- **决策 1（图标列无条件预留）**：双栏布局要求"无图标也占位"，故宽度计算与行渲染均无条件使用 ICON_COLUMN_WIDTH=24（16 图标 + 8 间距）。删除旧 hasIcon 条件分支，避免部分菜单（纯文本菜单）宽度计算与渲染不一致。
- **决策 2（CJK 测量策略）**：不走"整体乘 1.15"，改逐 CJK 字 +2.5vp——对中英混排（"将列设为..."、快捷键英文）更精确；叠加 8vp 平坦缓冲兜底子像素舍入/字体回退。fontFamily 显式 'HarmonyOS Sans' 与 Text 默认渲染一致，杜绝字体族不一致导致的测量偏差。
- **决策 3（parent 行 ▸ 箭头）**：父行末尾 ▸ 箭头宽度此前未计入面板宽度，加 PARENT_ARROW_WIDTH=12 防止箭头挤压标签触发折行。
- **决策 4（防折行兜底）**：maxLines(1)+TextOverflow.Ellipsis 属"皮带+背带"——即使测量差几 vp，文字截断显示省略号而非折行破坏面板高度。
