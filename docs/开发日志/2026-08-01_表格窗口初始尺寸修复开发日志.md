# 2026-08-01 工作日志：表格窗口初始尺寸修复（打开即缩小）

> 用户复核：新建表格依旧打开即最大化（上轮 resize(sizeHint) 未生效——sizeHint 本身大）；
> 用户明确所需"缩小窗口"= 现在真机 Table2 的状态（Table1 是全屏不想要）；缩小/还原后也应为

## 工作内容

1. **根因确认**：
   - QMdiArea::appendChild（qmdiarea.cpp:802-806）：对无 Qt::WA_Resized 的新子窗口自动缩放到
     `min(sizeHint, viewport)`。
   - Table 无自定义 sizeHint（QWidget 默认/布局推导），含原生列控制面板 → sizeHint 大 → 被铺满
     viewport（视觉最大化）。上轮 `resize(w->sizeHint())` 用的就是大的 sizeHint，故未生效。
   - Note（500×200）/MultiLayer（graph_width×graph_height）构造函数显式 setGeometry → WA_Resized
     → appendChild 跳过自动缩放 → 缩小。这是对齐基准。
2. **修复**：
   - Table.cpp `init()`：`setMinimumSize(400,300)` 后加 `setGeometry(0, 0, 600, 400)`（显式几何，
     设 WA_Resized；600×400 为含列控制面板的合理初始尺寸）。
   - ApplicationWindow.cpp `initTable()`：移除上一轮 `w->resize(w->sizeHint())`（避免大 sizeHint
     覆盖构造函数几何）。
3. **构建部署**：libentry.so 重建（Table.cpp 重编）→ HAP → 真机部署启动正常。

## 技术决策

- **决策 1**: 对齐 Note/MultiLayer 的"构造函数显式 setGeometry"模式，而非依赖 sizeHint——
  Table 的 sizeHint 因含列控制面板天然偏大，无法作为缩小尺寸依据。
- **决策 2**: 600×400 为含控制面板的合理初始尺寸；"缩小/还原"（restore/setNormal）回到该几何，
  满足用户"缩小后也是 Table2 状态"的要求。
