## 技术决策

- **决策 1: P0 步骤重排（先换插件后改代码）** — 原 v1 先改 MyAbilityStage 再换插件，
  在旧插件上无法通过验收且有 SIGSEGV 风险；v2 将插件替换（P0-1）置于代码改动（P0-2）之前。
- **决策 2: 能力探测 + 条件调用替代一刀切删除** — `setJsQuitFunction`/`qtMajorVersion`/
  `quitQtApplication` 在新插件符号扫描中缺失，但直接删除会分别导致 bootstrap 中断与
  JS 桥永不注册（假阴性）。采用 `typeof (qpa as any)[k] === 'function'` 探测后条件调用。
- **决策 3: deploy-libs.sh 持久化纳入 P0** — libs 目录由脚本生成且不在 git 跟踪内，
  不处理脚本则下次运行会把插件刷回 alpha_v6。
- **决策 4: 保留 C++ 线程回退通道** — qohos.cpp startQtNative 在 P0 验证通过前不删除。
